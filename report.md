# QFF 2026 Phase 1 — PS-O1 Exploratory Reduced-QAOA Experimental Report

> **Compliance status (13 Oct 2026):** The measured A/B comparison uses a five-qubit symmetry-fixed ansatz, which the organiser has **not officially approved** as the mandated six-vertex handling method. The full six-qubit problem cannot be directly deployed on five-qubit Processor A. The benchmark gate/noise parameters are provisional, and the published PDFs differ on whether processor connectivity is fixed or participant-defined. See `COMPLIANCE_NOTES.md`.

## 1. Task and reference solution

**Track:** Quantum Optimization. **PS-O1:** Max-Cut on Weighted Graphs, as specified in the 2026 Phase 1 Master Challenge Guide (page 4).

The benchmark generates `networkx.erdos_renyi_graph(n=6, p=0.5, seed=42)`, then assigns integer edge weights 1–5 with `random.Random(42)` over sorted edges. The actual 9 weighted edges and seeds are saved in `data/weighted_graph.json`. Exhaustive enumeration over all 64 assignments gives **optimal cut = 16**. One optimal six-bit assignment is **(0, 0, 1, 0, 1, 1)**.

We use the objective `C(x) = sum_(u,v) w_uv [x_u != x_v]`. As Max-Cut has global bit-flip symmetry, `C(x)=C(1-x)`, we fix vertex `x_0=0` and encode vertices 1–5 on five logical qubits, allowing deployment on five-qubit Processor A. The reduced objective is **exactly equivalent for finding the classical optimum**. However, a QAOA p=1 variational state on the 5-variable gauge-fixed subspace is **not generally equivalent to a standard six-qubit QAOA ansatz**; the comparison uses the same reduced ansatz on both A and B. Organiser confirmation of this symmetry encoding is recommended because the official guide does not state an encoding prescription.

## 2. QAOA and reference benchmark

The prepared state is `|+>^5`, with cost unitary `exp(-i * gamma * C)` (up to global phase) and mixer `exp(-i * beta * sum X_i)` for p=1. Edges not incident to vertex 0 use `rzz(-gamma*w)`; edges incident to fixed vertex 0 use `rz(-gamma*w)`. The circuit is built in `src/problem.py`.

A single pair of `(gamma,beta)` is optimized **once on an ideal logical statevector** (deterministic SciPy differential evolution, seed=42), then reused identically on A and B. No processor-specific parameter tuning occurs. Optimized gamma=0.208520075; beta=0.377498032. The ideal expected weighted cut on this *reduced* ansatz is **11.822893** (approximation ratio 73.8931%) against the classical optimum 16. The independent NumPy statevector probability calculation agrees with Qiskit Statevector within numerical tolerance.

## 3. Participant-designed processor models (Master Guide policy; kit differs)

Processor A: five physical qubits, sparse tree couplings `[[0, 1], [0, 2], [0, 3], [3, 4]]`. This architecture has only four links, forcing some requested two-qubit interactions to use longer paths. Processor B: nine physical qubits, connected 12-edge topology `[[0, 1], [0, 3], [1, 2], [1, 4], [2, 3], [2, 4], [2, 7], [2, 8], [4, 5], [4, 7], [5, 6], [6, 7]]`. This topology provides additional routes and physical qubits; it does not claim to model calibrated real IBM hardware. Both are undirected as modelled with bidirectional CX adjacency, and both use the same basis gates `{rz,sx,x,cx}`.

Processor models are generated by `processors/processor_A.py` and `processor_B.py`. The maps are **participant-defined**, which page 2 of the Master Guide explicitly permits, **but they do not match the fixed connectivity specified in the consolidated Challenge Kit sections 3.1–3.2**. Schematics are in `results/figures/processor_topologies.png`.

## 4. Controlled protocol (provisional settings)

- Exactly **five logical qubits** for the reduced six-node task on both processors; physical budgets A=5, B=9. Extra B qubits can be available to the transpiler as routing workspace, not as new logical variables.
- Qiskit transpilation: `optimization_level=1`, `seed_transpiler=42`, basis `rz/sx/x/cx` and **fixed initial layout** logical-to-physical `[0,1,2,3,4]` for both A and B.
- Qiskit Aer: 4096 measurement shots per simulation seed, baseline seeds `[43, 47, 53, 59, 61]`. Counts measure the logical qubits into the five original classical bit positions, so the cut evaluator decodes bit order correctly after transpilation.
- Same **provisional, not officially frozen** synthetic noise on A and B: single-qubit depolarizing p=0.001 for `rz`, `sx`, `x`; CX depolarizing p=0.005; symmetric readout-flip p=0.01. `rz` is treated as noisy by explicit *synthetic* choice, not as a noiseless virtual-Z gate.
- The unlimited-connectivity reference is transpiled with the same native basis and optimization level but without any coupling restrictions. Differences from it are **compilation overhead estimates**, not a direct count of physical SWAP operations.
- A separate routing diagnostic compiles with `swap` provisionally allowed in the basis. It is **not the device-executable native benchmark**; its SWAP count is a probe of the routing decomposition and may be sensitive to compiler choices.

## 5. Actual benchmark outcomes

| Metric | A | B |
|---|---:|---:|
| Physical qubits | 5 | 9 |
| Native circuit depth | 38 | 24 |
| Native CX gates | 24 | 15 |
| Native explicit SWAP gates | 0 | 0 |
| Diagnostic SWAP gates (non-native probe) | 4 | 1 |
| Additional CX vs unrestricted compilation | 12 | 3 |
| Initial-layout excess hop proxy | 6 | 2 |
| Noise-averaged cut (5 seeds) | 11.5347 | 11.5991 |
| Standard error between seed means | 0.0193 | 0.0156 |
| Mean noisy approx ratio | 72.092% | 72.494% |

Unrestricted 5-qubit native reference: depth=21, CX=12.

**Observed depth result:** B has lower native compiled depth. A depth=38 and B depth=24. The difference follows the compiler's layout/routing/gate optimization under the chosen connectivity, not an isolated gate-error advantage. Native `explicit_swap_count` may be zero even if routing was implemented through native CX sequences or other rewrites; do not interpret zero explicit SWAPs as zero routing cost. Consult the CX overhead, diagnostic SWAPs, and hop proxy together.

The noisy-score comparison uses a small number of seeds. **Do not claim a statistically certain performance advantage without an appropriate uncertainty analysis.** No actual hardware calibration, hardware runtime, or physical qubit fidelity data is used.

Limitations: six-node-to-five-qubit symmetry fixing is classically exact but changes the variational search space; fixed starting layout affects compilations; synthetic uniform gate/readout error is illustrative; compiler SWAP exposure depends on the basis decomposition; seed-to-seed simulation variance does not fully quantify uncertainty from alternative layouts or optimizer minima; all 9 B qubits need not be logically active.

## 7. Future architecture ideas (NOT implemented Phase 2)

A future participant-designed processor could selectively add edges joining distant logical interactions and reduce graph-path pressure, subject to hardware constraints. Such improvements require benchmark evidence; Processor C/D construction is intentionally outside Phase 1.

## 8. Reproducibility and AI disclosure

Pinned software in `requirements.txt`; regenerate configs via the two `processor_*.py` scripts and execute `main.ipynb` or `python run_experiment.py`. Assertions check statevector probabilities, reference optimum, device configs, topology reachability, and native basis consistency. Synthetic simulator seeds and benchmark settings are recorded in `results/experiment_metadata.json`.

AI assistance was used in code development, debugging, documentation, and experiment design. The participant/team must independently understand and confirm the benchmark before submission. Numeric results above are generated by **executed** Qiskit/Aer runs, not made-up estimates.

## 9. Executed full six-qubit QAOA — Processor B (separate experiment)

This **unreduced** p=1 QAOA benchmark covers the original six-node weighted graph using **six logical qubits** on **nine-physical-qubit Processor B**. Its numerical evidence was generated in Google Colab; the raw result is preserved in `results/full_six_qubit_reference.json`. The six-qubit circuit cannot be directly fitted onto Processor A's five physical qubits. Following the kit's capacity-reference interpretation, no fictitious six-qubit A run is reported.

**Comparability limit:** These six-qubit B results use the *eight-edge consolidated-kit B topology*, while the five-qubit A/B experiments above use *participant-designed* A and B topologies; they also use different ansätze and independently optimized parameters. Therefore, comparisons across sections 5 and 9 **cannot isolate architecture effects**. Only the within-section-5 A/B runs are controlled for a common five-qubit circuit. Neither noise settings nor this approach are represented as newly approved by the organisers. The six-qubit B result comes from one 4096-shot synthetic simulation, so no confidence interval for that result is asserted.

**Reproduce:** `python -m src.full_six_reference` runs the full-size benchmark and updates the JSON. The notebook `main.ipynb` includes that additional run before packaging.
