# PS-O1 Technical Report — Corrected Processor Models

## Problem and algorithm

Weighted Max-Cut on four logical vertices with five weighted edges, defined in `data/weighted_graph.json`. The classical optimum is 12. A single-layer QAOA ansatz is prepared with H gates, weighted RZZ interactions and RX mixers. The two QAOA angles are selected by an ideal statevector grid search and held fixed across processor comparisons.

## Processor architectures

Processor A is a participant-defined five-qubit branching graph. Processor B is a participant-defined nine-qubit connected graph, interpreted from the nine-node slide. The same four-logical-qubit workload is transpiled onto each with identical optimization level, seed, and initial logical layout. Configurations are generated by the two Python scripts in `processors/`.

## Controlled simulation

Uniform synthetic depolarizing noise is applied to `rz`, `sx`, `x` and `cx`, with probabilities 0.001 (single-qubit) and 0.01 (CX). Each processor is sampled over ten simulator seeds at 4096 shots. We also compare initial layouts and vary CX error strength. These models do not reproduce calibrated quantum hardware.

## Correctness and routing

The notebook measures the four logical classical bits **before transpilation**, avoiding ambiguity about the physical qubit locations. An exact statevector total-variation-distance assertion checks the noiseless compiled output distribution against the ideal QAOA circuit. Explicit SWAP counts can be zero because SWAP routing may already be decomposed into CX gates; the post-transpilation CX count and depth must be considered.

## Results and interpretation

These numbers were exported by the user's successful Google Colab notebook run using the corrected participant-defined processor models. The exact noiseless statevector assertions completed without reported errors. The values are simulation outputs, not measurements from physical quantum hardware.

| Metric | Processor A | Processor B |
|---|---:|---:|
| Physical qubits | 5 | 9 |
| Transpiled circuit depth | 40 | 29 |
| CX gates | 16 | 16 |
| Explicit SWAP gates | 0 | 0 |
| Mean weighted cut (10 seeds × 4096 shots) | 9.9107 | 9.9216 |
| Standard deviation across seed means | 0.0359 | 0.0431 |
| Approximation ratio (optimum = 12) | 0.8259 | 0.8268 |

Processor B compiled to a circuit 27.5% shallower than A under the fixed initial layout. Both circuits used the same number of CX gates, and neither reported explicit SWAP operations after decomposition. The small observed difference in mean weighted cut (+0.0109 for B relative to A) is comparable to the across-seed variability and should **not** be claimed as a statistically established improvement.

The noise-sensitivity study (`results/tables/noise_sensitivity.csv`) shows declining mean cut as CX depolarizing noise increases for both architectures. For Processor A the means range from 10.1310 (CX error 0) to 9.3901 (CX error 0.03); for B from 10.1499 to 9.5333. Single-qubit depolarizing noise remains fixed at 0.001 even at CX error 0.

**Interpretation:** Under the chosen graph, fixed layout, basis, and uniform noise assumptions, B reduces circuit depth but does not significantly reduce CX count or convincingly improve solution quality. This is a meaningful architecture/resource comparison, not evidence that a nine-qubit device is universally superior. The layout sensitivity table further illustrates dependence on initial placement. Explicit SWAP counts alone cannot identify all routing overhead when routing has been decomposed into CX gates.

## Limitations

Small four-node instance; single QAOA layer; grid-based rather than gradient-based angle optimization; participant-defined architectures and synthetic uniform noise; no readout error or calibrated device-specific gate errors; layout and routing results depend on transpiler configuration. Do not interpret differences in sample means as statistically established without uncertainty analysis.
